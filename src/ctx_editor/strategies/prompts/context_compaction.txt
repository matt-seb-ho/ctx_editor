## Your Task

Using the conversation and reviewer's notes as raw material, produce compacted context with two sections:

1. **Task Specification**: A clean, consolidated statement of what the user wants. Derive this from the user's actual messages in the conversation — the reviewer's task spec is guidance but may contain errors. Include all constraints, requirements, and details the user specified. Do NOT add requirements the user did not state.

2. **Work Completed So Far**: Summarize the correct, relevant work the assistant has done that should be preserved. Use the reviewer's "what looks right" notes as guidance for what to keep. Omit incorrect work, dead ends, and abandoned approaches — do not mention them at all.

Output format — use these exact tags:

<task_spec>
[Clean, consolidated task specification derived from user messages]
</task_spec>

<work_so_far>
[Summary of correct work completed, or "None" if nothing is salvageable]
</work_so_far>

Important:
- Do NOT include the reviewer's issues or error descriptions in your output. The point is to remove harmful content from context, not redescribe it.
- Do NOT suggest asking the user for clarification. The user cannot be asked questions.
- Be specific and concrete. Preserve exact values, formulas, column names, function signatures, etc. from the user's messages.
- If the reviewer's task spec contradicts what the user actually said in the conversation, trust the user's messages.
