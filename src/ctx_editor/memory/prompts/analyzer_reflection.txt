The cheatsheet captures lessons for the conversation analyzer — the component that reviews

## What the Analyzer Does

The analyzer independently reviews a multi-turn conversation and produces a structured analysis:
- **Task Spec (user intent)**: A clean specification derived ONLY from user messages — no
  assistant assumptions. This separates what the user actually asked for from what the assistant
  decided to do.
- **What Looks Right (aligned)**: Parts of the assistant's approach that correctly address the task.
- **What Needs to Change (issues)**: Where the assistant's approach contradicts or deviates from
  user requirements. If substantive issues are found, the analysis triggers an intervention.

The analysis is used in two strategies:

**S1 (Append Analysis)**: The analysis is appended to the conversation so the assistant can see
it before its next response. The assistant sees the full conversation history with the analysis
interleaved. Goal: the assistant course-corrects on its own after reading the critical review.

**S2 (Context Edit)**: When issues are found, the old conversation is replaced with compacted
context containing only the task spec and aligned work. This removes "hard attention" — the
assistant's previous wrong reasoning that anchors it to incorrect approaches. The assistant then
responds with clean context, free from its own earlier mistakes.

## Evaluation Environment

The conversations use a sharded-disclosure setup: the user reveals problem information
incrementally across turns. The user does NOT answer clarifying questions — they only
provide pre-scripted information shards. If the assistant asks a clarifying question,
it wastes a turn because the user will ignore it and reveal the next shard regardless.
The cheatsheet should NOT recommend asking clarifying questions or seeking confirmation.
Instead, the assistant should work with available information and refine as more arrives.

## How the Cheatsheet Controls Behavior

The analyzer's prompt defines WHAT to produce — the input/output format and high-level goal.
But the prompt is intentionally lean. The cheatsheet controls HOW the analyzer actually works:

- **Strategies and sequencing**: Specify subgoals and their order.
  e.g., "First gather all user-stated constraints into a checklist, then evaluate the assistant's
  approach against each one" or "Check output format requirements last, after verifying logic"
- **Diagnostic patterns**: What conversation patterns indicate specific types of errors.
  e.g., "When the assistant gives a very confident early answer, check whether it's grounded in
  user requirements or just plausible-sounding"
- **Concepts and mental models**: Reusable frameworks for analysis.
  e.g., "Distinguish 'did something wrong' from 'did something not asked for' — the first needs
  correction, the second needs removal"
- **Pitfalls to avoid**: Common analyzer mistakes to watch for.
  e.g., "Don't flag ambiguity when the user's example clearly resolves it"
- **Successful strategies**: What worked well in past analyses.
  e.g., "When the user provides test cases, use them as ground truth to verify the assistant's
  logic rather than reasoning abstractly"
