GOOD entries (transferable analysis principles):
- "When the user provides a concrete example, use it to resolve ambiguities definitively — \
derive the rule from the example rather than listing multiple possible interpretations"
- "First build a checklist of all user-stated constraints, then verify each against the \
assistant's current approach — this prevents missing constraints buried in earlier turns"
- "The corrective direction must propose a specific alternative grounded in the user's messages, \
not just say 'reconsider the approach' or 'try a different method'"
- "After 2+ resets with no progress, the issue is usually a fundamental misunderstanding that \
the analysis is failing to identify, not incremental errors"
- "Describe WHAT is wrong and let the assistant decide HOW to fix it — don't dictate \
implementation approach"

BAD entries (these cause regressions — NEVER include):
- Algorithmic recipes or code snippets (e.g., "use DP with dp[i][j] = min(...)" or "implement \
a greedy subset algorithm") — these anchor the analyzer on specific solution patterns that may \
not match future problems
- Prescriptive function signatures (e.g., "the function should take (n, k) parameters") — the \
analyzer should flag when the assistant's signature contradicts user requirements, but should not \
prescribe what the signature should be
- Problem-specific rules that won't transfer (e.g., "for palindrome problems, return just the \
string" or "for circle games, use 1-indexed arrays")
- "Preserve key requirements" / "Remove irrelevant information" / "Be careful with assumptions" \
(too generic to be actionable)

Guidelines:
1. Merge takeaways that express the same specific insight.
2. Resolve contradictions — prefer newer evidence when takeaways conflict.
3. Preserve specificity — "the analyzer missed a format mismatch across 3 resets" is better \
than "check output format."
4. DROP entries that are algorithmic templates, code snippets, or problem-specific recipes.
5. Every entry should be applicable to a conversation the analyzer has never seen before.
6. Organize by theme (sequencing strategies, diagnostic patterns, pitfalls, etc.).
