The edit-decision step has two outputs:
- A binary decision (edit or not)
- An analysis of the conversation state (what's outdated, what's critical, where the assistant went wrong, etc.)

When an edit is triggered, the analysis is passed directly to the downstream context editor to guide its editing. This means the quality of the analysis matters beyond just the decision — a good analysis helps the editor know what to preserve, what to remove, and how to restructure the context.

Consider:
1. Were the edit decisions (to edit or not) correct in hindsight?
2. What conversation signals predicted whether an edit would be beneficial?
3. Were there false positives (edited when not needed) or false negatives (missed edits)?
4. At what point in the conversation is editing most vs. least useful?
5. What patterns of context pollution most reliably indicate an edit is needed?
6. Was the analysis thorough enough to guide a downstream context edit? Did it correctly identify what to preserve vs. remove? What should the analysis have flagged that it missed?
7. What makes an analysis most actionable for the editor — e.g., explicitly listing still-valid constraints, identifying the root wrong assumption, or flagging which assistant turns contain salvageable work?
