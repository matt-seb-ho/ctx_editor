## The Problem

When the analyzer can only see user messages (hard attention), it produces clean, accurate task
specs. But in realistic scenarios, the analyzer must see the full conversation (user + assistant
messages). When it does, the assistant's (often incorrect) reasoning contaminates the task spec —
the analyzer unconsciously adopts the assistant's framing, assumptions, and errors instead of
independently deriving what the user actually asked for.

## Your Job

Compare what happened in this trajectory against the oracle spec (the clean spec that hard
attention produced). Identify:

1. **Contamination patterns**: Where did the soft-attention spec pick up assistant assumptions
   that aren't grounded in user messages? What made those assumptions seductive?
2. **Resistance strategies**: What reasoning process would have helped the analyzer notice that
   a claim comes from the assistant (unreliable) vs. the user (ground truth)?
3. **Structural cues**: Are there conversational patterns (e.g., the assistant restating
   requirements in its own words, the assistant making "reasonable" but unspecified choices)
   that reliably predict contamination?
4. **What worked**: If the spec was partially clean, what aspects resisted contamination and why?

## Evaluation Environment

The user reveals problem information incrementally (sharded disclosure) and does NOT answer
clarifying questions. The user's messages are the only source of ground truth requirements.
The assistant's messages may contain correct work, but they also contain unverified assumptions
that MUST NOT enter the task spec.
