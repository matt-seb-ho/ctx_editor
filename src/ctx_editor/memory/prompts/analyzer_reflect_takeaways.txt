## What the Analyzer Does

The analyzer independently reviews multi-turn conversations to identify where the assistant's
approach has diverged from what the user actually asked for. It produces:
- **Task Spec**: Clean specification from user messages only (no assistant assumptions)
- **What Looks Right**: Parts of the assistant's approach that are correctly aligned
- **What Needs to Change**: Issues where the assistant contradicts user requirements

The analysis is then used in one of two ways:
- **S1 (Append)**: Analysis is shown to the assistant as additional context before its next
  response. The assistant sees the full history plus the analysis interleaved.
- **S2 (Context Edit)**: If issues are found, the old conversation is replaced with compacted
  context (task spec + aligned work only), removing the assistant's wrong reasoning so it can
  start fresh without anchoring on previous mistakes.

## How to Read the Trace

The trace shows the conversation with `[conversation analysis]` blocks interleaved at the point
they occurred — between user and assistant turns, reflecting the actual flow. For S2 traces,
`→ Decision: EDIT/NO EDIT` shows whether context was rewritten, and `NEW CONVERSATION` markers
show where the old context was discarded and replaced with compacted context.

## What Makes Good Takeaways

The analyzer's prompt is intentionally lean — it defines WHAT to produce (task spec, aligned,
issues) but not HOW to analyze. The cheatsheet fills in the "how":

- **Sequencing**: e.g., "First gather all user-stated constraints, then check each against
  the assistant's approach" — the cheatsheet can control the analyzer's inner process
- **Diagnostic patterns**: e.g., "When you see X in the conversation, it usually means Y"
- **Pitfalls**: e.g., "The analyzer did X but should have done Y because..."
- **Successful strategies**: What worked well and is worth repeating
