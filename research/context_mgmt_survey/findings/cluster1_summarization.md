# Cluster 1: Summarization and Compaction

Survey date: 2026-08-03.  
Focus: methods that manage long context by summarizing or compressing the conversation/trace.  
Framing axes: **ENTANGLEMENT** (later user turns reference assistant phrasings, so lossy compression breaks dereferencing) and **STATEFULNESS** (persistent environment state must survive the compression intact).

| **Recursive Dialogue Summarization** (Wang et al.) | Neurocomputing / arXiv 2023 | LLM recursively merges prior summary with the newest dialogue chunk; only the updated summary is forwarded. | Verbatim assistant phrasings are folded into summaries; anaphoric follow-ups ("the approach you just described") cannot be resolved against a summary. | Multi-hop merges trade state fidelity for fluency; quantitative values and tool-output details degrade across summarization steps. | https://arxiv.org/abs/2308.15022 |
| **LLMLingua** (Jiang et al.) | EMNLP 2023 | Coarse-to-fine iterative token-dropping via small-LM perplexity, with a budget controller for compression ratio. | Independent token-level scoring ignores future-turn referential needs; pronoun antecedents scored as low-perplexity are eligible for deletion, breaking coreference chains. | Token drops can corrupt structured outputs (JSON, code, SQL), severing exact values required for continued state tracking. | https://arxiv.org/abs/2310.05736 |
| **LongLLMLingua** (Jiang et al.) | ACL 2024 | Question-aware context compression that re-ranks segments by relevance to the current query before dropping tokens. | Relevance is scored against the *current* question, not future turns; assistant turns scored low-relevance are compressed away, silently breaking later user references. | Relevance scoring for QA does not account for agent-style state transitions; non-question-relevant environment observations are dropped even when they encode critical state. | https://arxiv.org/abs/2310.06839 |
| **LLMLingua-2** (Pan et al.) | ACL Findings 2024 | Bidirectional encoder trained via GPT-4 data distillation to classify each token as keep/drop for extractive, task-agnostic compression. | Classifier trained on information-retrieval tasks, not dialogue; no model of what later turns will dereference; inter-turn reference chains are invisible to the keep/drop decision. | No explicit state-continuity objective; tokens locally unimportant to the retrieval signal may encode downstream-critical environment state and still be dropped. | https://arxiv.org/abs/2403.12968 |
| **MEMENTO** (Kontonis et al., MSR) | arXiv 2026 | Fine-tuned model segments reasoning into blocks, compresses each into a dense memento; relies on dual text+KV-cache channel for full fidelity. | Designed for single-turn CoT; cross-turn references between user and assistant are not modeled; the memento of an assistant block loses the specific formulation that user follow-ups might reference. | Removing KV cache drops accuracy 15 pp on AIME24, indicating state leaks through the cache channel; pure-text mementos alone do not reliably encode all task state. | https://arxiv.org/abs/2604.09852 |
| **ACON** (Kang et al., MSR) | ICML 2026 | Failure-driven optimization of natural-language compression guidelines; distills result into a smaller compressor model. | Guidelines optimize for task-relevant state, not inter-turn referential links; assistant responses are compressed by task-relevance, not by referential necessity. | Strongest method for long-horizon stateful agents (designed for this); but fixed guidelines may miss emergent state transitions outside the training distribution. | https://arxiv.org/abs/2510.00615 |
| **Anthropic Compaction API** (Anthropic) | Production 2026 | Server-side summarization triggered at a configurable token threshold; all messages prior to the compaction block are discarded and replaced by a single summary. | "All content blocks prior to the latest compaction block are ignored" — verbatim assistant statements survive only if the summarizer replicates their exact phrasing, which is not guaranteed by default. | Custom summarization instructions can request specific state artifacts, but without them the default summary may omit file paths, variable bindings, or tool-output values. | https://platform.claude.com/docs/en/build-with-claude/compaction |
| **Cline Auto-Compact** (Cline) | Production 2025 | Monitors token count; when threshold approached, sends history to a summarizer that produces a condensed narrative replacing prior history. | Narrative summary captures story arc but not precise phrasings; references like "the second option you gave" cannot be resolved from a narrative. | No formal evaluation on persistent-environment tasks (tau2-bench style); narrative-integrity claim is qualitative and unverified against stateful benchmarks. | https://docs.cline.bot/features/auto-compact |
| **Cursor /summarize** (Cursor) | Production 2024 | On-demand or automatic summarization when context window approaches limit; generates a summary replacing prior conversation turns. | Community-reported inconsistency and bugs; even when functioning, fine-grained inter-turn references are not preserved and the exact assistant phrasing users reference is lost. | No mechanism for tracking file system or code state beyond the narrative; community reports document code artifacts being silently dropped after summarization. | https://cursor.com/changelog/1-6 |

## Positioning Note

Summarization and compaction — not the assistant-omit baseline from Huang et al. (MIT) — are the **production incumbent** for context management. Every major coding-agent platform (Claude Code / Anthropic Compaction API, Cline, Cursor) ships summarization as its primary long-context strategy, making this the most important class to characterize and position against. The structural failure shared across all nine entries is what we call **compress-then-continue**: these methods summarize the history *before* resolving the references embedded in it, implicitly assuming the downstream model can re-derive whatever context subsequent turns require. Under high ENTANGLEMENT this assumption breaks systematically — a user saying "wait, can you expand on approach B?" after a summary that collapsed "approach A and approach B (preferred)" into "discussed two approaches" has no recoverable referent. Under high STATEFULNESS, the second failure mode is equally sharp: learned summarizers (LLMLingua-*, MEMENTO, ACON) optimize token efficiency and task-relevant signal, not the verbatim reproduction of state-critical token sequences (e.g., database schema fragments, file modification timestamps, accumulated test-failure counts). Our proposed **decontextualize-then-edit** method inverts the order: it first resolves all inter-turn references against the assistant turns *before* any pruning, so the editable representation is already reference-free when the surgical rewrite occurs. This means our method survives the ENTANGLEMENT axis by construction, and the explicit state-preservation pass in the edit phase addresses STATEFULNESS in a way that generative summarization cannot guarantee without per-domain custom instructions. Attacking summarization/compaction rather than assistant-omit is therefore the stronger framing: it targets a richer, more realistic baseline and the one users are actually running today.
