# Cluster 3: Retrieval-over-History / Conversational RAG

Survey date: 2026-08-03.  
Focus: methods that manage long conversation history by retrieving relevant past turns on demand, rather than keeping the full context or compressing it.  
Framing axes: **ENTANGLEMENT** (later turns refer to prior assistant phrasings; elliptical queries like "reverse that" have no keywords to retrieve on) and **STATEFULNESS** (persistent environment state that must be tracked; accumulated results cannot be reassembled from retrieved fragments).

## Positioning Note

Retrieval-over-history is the natural alternative to keeping the full context or compressing it: retrieve only the past turns relevant to the current step. The cluster divides into two sub-lineages. The first is **conversational query rewriting** (CANARD, QReCC, CONQRR, ConvGQR), which addresses the precondition for any retrieval strategy: the current user utterance must be made self-contained before a retriever can match it against stored history. These systems are the closest existing analogue to our "decontextualize" step. The critical distinction is *why* each side decontextualizes: query-rewriting systems resolve references so that an off-the-shelf retriever can find a relevant passage in a static corpus — the goal is improved retrieval recall on a fixed knowledge base. Our decontextualize step resolves references so that subsequent *context editing* can safely prune the assistant turns that the references depend on — the goal is enabling safe rewriting of a mutable, live conversation history. This is a fundamentally different operation: query-rewriting produces a one-shot search key and discards the resolution; our approach produces a persistent rewrite that integrates resolved references into the ongoing conversation context so that pruning the original turn does not break the semantics. The second sub-lineage is **memory-bank and adaptive retrieval** (MemoryBank, RAGate, mtRAG), which applies retrieval to the conversation history itself rather than an external corpus. These systems break along both axes in a structurally predictable way. On ENTANGLEMENT, the failure is irreducible: when a user utterance contains no retrievable signal (pure ellipsis, opaque anaphora, procedural back-reference), no amount of retrieval sophistication recovers the referent — the information lives in the conversation structure, not in any retrievable token. Liu et al.'s "lost in the middle" result then compounds the failure: even successfully retrieved turns suffer positional attention loss if placed mid-context. On STATEFULNESS, the failure is equally fundamental: retrieval returns fragments, but accumulated environment state is a running function of the entire prior history — it is not stored as any individual fragment and cannot be assembled by concatenating retrieved excerpts. tau-bench makes this concrete: an agent tracking flight bookings cannot recover the current reservation state by retrieving the turn where the flight was first mentioned; it needs to replay the sequence of modifications. Our method sidesteps both failure modes by resolving references *before* pruning (addressing ENTANGLEMENT) and by explicitly preserving state-critical turns during the edit phase (addressing STATEFULNESS), treating context editing as a semantics-preserving rewrite rather than a retrieval problem.
