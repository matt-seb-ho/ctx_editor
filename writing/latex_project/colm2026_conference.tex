\begin{abstract}
Large language models suffer systematic performance degradation in multi-turn conversations when task specifications are revealed incrementally---a phenomenon documented as ``Lost in Conversation''~\citep{laban2025lost}. This degradation reflects a failure of \emph{executive function}: the model cannot inhibit attention to its own prior (often incorrect) reasoning, flexibly update its working representation of the task, or shift strategy when early approaches fail. Prior mitigations discard all assistant context~\citep{huang2026context,khalid2025ergo}, which is effective only when rederivation is cheap. We investigate whether LLMs can instead perform \emph{self-aware context curation}: an external agent makes the model aware of its own context pollution by re-reading the conversation, identifying executive function failures, and surgically editing context to preserve correct work while removing harmful anchoring content. We decompose the analysis into subtasks---extracting a clean task specification from user messages, then comparing it against the assistant's work---to externally implement the selective attention and distractor inhibition that current LLMs lack internally. A striking finding is that prior assistant messages act as a \emph{cognitive hazard}: even a model prompted as an independent reviewer produces degraded analysis when exposed to those messages, demonstrating that context pollution impairs not just the conversational assistant but any model processing the same context. On the Lost in Conversation benchmark, our methods improve accuracy substantially (e.g., 60\% to 90\% on math, 16\% to 72\% on code). Critically, we demonstrate that blanket assistant omission---the strongest prior baseline---is catastrophically destructive in realistic agentic settings: on the tau2-bench tool-use benchmark, omitting assistant messages drops performance from 55\% to 0\%, while our context editing approach achieves 55--60\%, and on WildChat conversations, our best strategy achieves 84--86\% quality win rates against both full context and assistant omission while intervening on only 72\% of turns. These findings establish that intelligent context curation, not wholesale context removal, is necessary for robust multi-turn LLM deployment.
\end{abstract}

\section{Introduction}
\label{sec:intro}
%% ============================================================

The deployment of large language models increasingly involves multi-turn conversations. Users rarely specify complete requirements upfront; instead, they iteratively clarify, correct, and extend their requests across multiple exchanges. This conversational pattern is natural for humans but creates a fundamental problem for LLMs: once the model commits to an interpretation in an early turn, the resulting reasoning persists in context and anchors all subsequent generation, even when later user messages contradict the initial assumptions.

\citet{laban2025lost} quantified this through the ``Lost in Conversation'' (LiC) framework, a large-scale simulation across 15 LLMs and 6 task domains. Their core finding is striking: the performance gap between single-turn and multi-turn settings is driven primarily by \emph{unreliability} (112\% increase), not reduced \emph{aptitude} (only 16\% decrease). The capability is preserved, but the model fails to access it reliably. Subsequent work has attributed this degradation to what \citet{huang2026context} term \emph{context pollution}: the assistant's prior outputs introduce errors, incorrect assumptions, and speculative content that accumulate across turns, anchoring future generation on flawed foundations.

We frame this degradation as a failure of \textbf{executive function}---the higher-order cognitive processes that manage attention, inhibit prepotent but incorrect responses, and flexibly update working memory~\citep{miyake2000unity,diamond2013executive}. In human cognition, executive function enables a problem-solver to recognize when an approach is failing, suppress the impulse to continue down a familiar path, and redirect effort toward more promising alternatives. Current LLMs lack this regulatory capacity: they cannot selectively inhibit attention to their own prior reasoning, even when that reasoning is demonstrably wrong. The result is precisely the pattern \citet{laban2025lost} document---preserved aptitude with degraded reliability.

We observe two distinct mechanisms driving this degradation:

\begin{enumerate}
    \item \textbf{User intent fragmentation.} In multi-turn conversations, the user's actual request is scattered across turns---paraphrased, revised, and buried in conversational noise. The model must reconstruct what the user wants from incomplete, non-linear input, and frequently fails.

    \item \textbf{Reasoning anchoring.} The assistant's prior (often incorrect) reasoning remains in context and anchors future responses. Even when later user messages contradict earlier assumptions, the model cannot un-see its own mistakes---a direct failure of inhibitory control.
\end{enumerate}

Existing mitigations---omitting all assistant messages~\citep{huang2026context}, entropy-triggered context resets~\citep{khalid2025ergo}---address both problems at once by discarding everything the assistant has said and effectively starting over. On the LiC benchmark, where rederivation is cheap and user messages fully specify the task, this works well. But these approaches cannot generalize to realistic settings where the assistant's prior work is essential: multi-step coding, iterative design, tool-use agents. In such settings, the challenge is not to discard context but to \emph{curate} it---preserving what is correct while removing what is harmful.

This paper investigates whether LLMs can perform this self-curation through what we term \emph{self-aware context curation}. The core idea is to make the model aware of its own executive function limitations by having a separate agent re-read the conversation, identify where the assistant has gone off course, and intervene in the context before the next response. We use the term ``self-aware'' with deliberate caveats: we do not claim phenomenological self-awareness, but rather a functional analog---the system is designed to detect and compensate for its own systematic failure modes, much as a human might use external checklists to compensate for known cognitive biases. The model does not intrinsically know it is susceptible to context pollution; we \emph{make} it aware by structuring the agent to look for exactly this class of failure.

Our approach decomposes the analysis into two subtasks, externally implementing the executive functions of selective attention and distractor inhibition:

\begin{itemize}
    \item \textbf{Task specification extraction} (selective attention). A separate LLM call extracts a clean, consolidated task specification from user messages alone, reconstructing fragmented intent without the assistant's interpretive lens. This implements the attentional control that the model lacks---focusing on user intent while filtering out the assistant's potentially misleading framing.

    \item \textbf{Approach evaluation} (monitoring and inhibition). A second call compares this clean specification against the full conversation to identify what the assistant got right and where it diverged. This implements the performance monitoring and error detection functions that enable course correction.

    \item \textbf{Meta-cognitive learning.} A Dynamic Cheatsheet~\citep{suzgun2025cheatsheet} accumulates transferable self-reflection principles across problem instances, enabling the system to learn from past executive function failures.
\end{itemize}

The reason for decomposing the analysis---rather than having a single call assess the full conversation---is our most striking finding: prior assistant messages act as a \emph{cognitive hazard} for the analyzer. Even when prompted as an independent reviewer with no role obligation to the assistant, the model's analysis is severely degraded by exposure to the assistant's messages. The mechanism is not fully understood---it may be attention-based anchoring, implicit role consistency, or some other property of how LLMs process multi-party conversation---but the effect is unambiguous: analysis quality collapses to baseline or worse when the analyzer sees assistant messages during intent extraction (Section~\ref{sec:cognitive-hazard}). This is not a prompting failure that more careful instructions could fix; we tried.

This means the problem is recursive: we want the model to identify what is bad in its own context, but the bad context impairs the model's ability to identify it. Structurally excluding assistant messages from the intent extraction step breaks this recursion on LiC, where user messages alone fully specify the task. But this structural exclusion is benchmark-specific---it works precisely because LiC tasks are self-contained and rederivation is cheap.

Critically, we demonstrate that this benchmark-specificity extends to prior work's strongest baseline. On the tau2-bench tool-use benchmark~\citep{yao2024tau}, blanket assistant omission~\citep{huang2026context} is \emph{catastrophically} destructive: performance drops from 55\% to 0\% as the agent loses all tool results and enters infinite re-lookup loops. Our context editing approach maintains or improves upon the baseline (55--60\%), and on WildChat conversations~\citep{zhao2024wildchat}, our best strategy achieves 84--86\% quality win rates against both full context and assistant omission while intervening on only 72\% of turns ($n$=179 turns across three strategies). These results establish that intelligent context curation---not wholesale context removal---is necessary for robust multi-turn deployment.

We present investigations along three axes:

\begin{enumerate}
    \item \textbf{Externalized executive function on LiC.} Subtask decomposition with structural attention control achieves substantial improvements, with memory-based learning further amplifying analysis quality (Section~\ref{sec:lic-results}).

    \item \textbf{Agentic evaluation on tau2-bench.} Context editing outperforms the baseline while blanket omission catastrophically fails, demonstrating the necessity of selective curation in stateful settings (Section~\ref{sec:tau2-results}).

    \item \textbf{Realistic settings: CollabLLM and WildChat.} Context curation improves accuracy in genuinely collaborative interactions. On WildChat, we compare three intervention strategies head-to-head: Gated Reset achieves 84--86\% quality win rates against both baselines while intervening on only 72\% of turns, confirming the value of intelligent gating over unconditional intervention (Section~\ref{sec:collab-results}).
\end{enumerate}

\section{Related Work}
\label{sec:related}
%% ============================================================

\subsection{Multi-turn performance degradation}

\citet{laban2025lost} introduced the Lost in Conversation (LiC) framework, demonstrating that LLMs suffer systematic performance degradation in multi-turn, underspecified conversations. Their methodology takes single-turn problems and ``shards'' them: the complete specification is split into pieces revealed incrementally by a simulated user. The key findings are: (1) performance drops 39\% on average, (2) degradation is primarily unreliability (+112\%) rather than reduced aptitude ($-$16\%), (3) all 15 tested models exhibit similarly high multi-turn unreliability, and (4) interventions within the same conversation context fail to close the gap---only starting a new conversation with consolidated information recovers performance.

\subsection{Context resetting and omission}

\citet{khalid2025ergo} proposed ERGO, which monitors token-level Shannon entropy at each turn and triggers a context reset when the entropy delta exceeds a calibrated threshold. Upon reset, all prior user messages are summarized into a single prompt and all assistant messages are discarded. ERGO achieves a 56.6\% average performance gain on LiC. However, it requires logprob access and discards all assistant work entirely.

\citet{huang2026context} investigated whether prior assistant responses help or hurt, coining the term \emph{context pollution}. They found that omitting all prior assistant responses frequently improves response quality, and that one-sentence summaries outperform both full context and full omission. Their key insight directly supports our thesis that intelligent context curation beats both extremes. However, their approach makes a binary per-turn choice (keep all or omit all). We adopt their terminology and build on their finding that assistant messages are the primary source of degradation, while demonstrating that their omission approach fails catastrophically in agentic settings (Section~\ref{sec:tau2-results}).

\subsection{Executive function in cognitive science}

Executive function refers to the set of cognitive processes that regulate attention, inhibit prepotent responses, and flexibly update working representations~\citep{miyake2000unity}. \citet{diamond2013executive} identifies three core components: inhibitory control (suppressing inappropriate responses), working memory updating (revising held information), and cognitive flexibility (switching between strategies). We draw on this framework to characterize what LLMs lack in multi-turn settings and to motivate our external implementation of these capacities. The connection is functional rather than mechanistic---we do not claim LLMs have cognitive architectures analogous to human prefrontal cortex, but that the \emph{behavioral} failures align with executive function deficits.

\subsection{Test-time scaling and self-reflection}

The broader test-time scaling literature investigates how additional inference-time compute can improve model performance, including chain-of-thought reasoning~\citep{wei2022chain}, self-consistency~\citep{wang2023selfconsistency}, and tree-of-thought search~\citep{yao2024tree}. These methods focus on single-turn settings, scaling compute within a single generation. Our work extends test-time scaling to the \emph{multi-turn} setting, where the challenge is not generating a better single response but managing accumulated context across turns. The key mechanism is different: rather than searching over possible outputs, we curate the \emph{input context} presented to the model.

\subsection{Dynamic Cheatsheet}

\citet{suzgun2025cheatsheet} introduced the Dynamic Cheatsheet, a mutable text document that accumulates task-relevant knowledge across problem instances at test time without gradient updates. We adapt this for context curation, targeting the cheatsheet at the analyzer's executive function rather than the task-solving assistant itself.

\subsection{Agentic benchmarks}

Tau2-bench~\citep{yao2024tau} evaluates LLM agents on realistic customer service tasks requiring tool use, multi-turn dialogue, and stateful problem resolution. Unlike LiC's self-contained tasks, tau2-bench conversations involve API calls whose results are essential context for subsequent reasoning---making blanket context removal fundamentally incompatible with task success.

\section{Methods}
\label{sec:methods}
%% ============================================================

\subsection{Problem setting}
\label{sec:problem-setting}

We adopt the LiC simulation framework for our primary evaluation. A single evaluation instance consists of: a task with fully-specified question $q$ and ground truth answer $a$; a sharding of $q$ into $k$ shards $\{s_1, \ldots, s_k\}$ that partition the specification; a simulated user that reveals shards incrementally; an assistant (the model under evaluation); and a system agent that classifies responses and evaluates correctness.

For agentic evaluation, we extend to tau2-bench~\citep{yao2024tau}, where the assistant is an agent with access to tools (API calls) that must diagnose and resolve customer service issues through multi-turn dialogue.

\subsection{Conversation analysis via subtask decomposition}
\label{sec:decomposition}

The central challenge is getting an LLM to accurately assess what has gone right and wrong in a conversation. Rather than asking a single model to perform this analysis in one pass over the full conversation, we decompose it into two subtasks with different context windows---externally implementing the executive functions of selective attention and distractor inhibition.

\paragraph{Subtask 1: Task specification extraction (selective attention).}
The model sees only the system message and all user messages---no assistant responses. It produces a consolidated task specification: a clean restatement of what the user is asking for. The system message grounds the specification in the correct output format (e.g., SQL against a specific schema, function calls with specific signatures), preventing over-elaboration. By physically excluding assistant messages, we implement attentional control that the model cannot perform internally---focusing on user intent while filtering out potentially misleading assistant framing.

\paragraph{Subtask 2: Approach evaluation (monitoring and inhibition).}
The model sees the task specification from Subtask~1 plus the full conversation history, and optionally a memory cheatsheet. It produces an assessment of what the assistant got right (\texttt{aligned}) and what contradicts the specification (\texttt{issues}). This implements performance monitoring: comparing the current trajectory against the intended goal.

The reason for this decomposition is empirical, not aesthetic. The model cannot reliably extract user intent when assistant messages are present---it anchors on the assistant's framing even when instructed to focus on user messages. By physically excluding assistant messages from Subtask~1, we design around this limitation rather than attempting to prompt through it. We show in Section~\ref{sec:cognitive-hazard} that including assistant messages in Subtask~1 collapses the system's effectiveness to baseline or worse.

\subsection{Context strategies}
\label{sec:strategies}

The analysis produces a structured artifact containing a consolidated task specification, an assessment of what the assistant got right (\texttt{aligned}), and identified divergences (\texttt{issues}). Three intervention strategies use this artifact with increasing levels of context modification:

\paragraph{Augment.} The analysis artifact is appended to the conversation before the assistant's next turn. The full history is preserved---the analysis provides corrective signal but polluting content remains visible. This is the lightest intervention: no context is removed, and the assistant must integrate the corrective analysis with the existing (potentially misleading) conversation.

\paragraph{Reset.} The analysis artifact populates a structured template that \emph{replaces} the entire conversation history. All prior messages are removed; the task specification and aligned content are preserved in a clean format. Issues guide the edit but are not reintroduced into context. This removes polluting content entirely at the cost of discarding any information not captured by the analysis.

\paragraph{Rewrite.} An additional LLM call reads the analysis artifact and generates a restructured context, giving the model flexibility to shape the presentation beyond what a fixed template can express. This is the most expressive intervention but introduces an additional generation step that may editorialize or lose concrete details (Section~\ref{sec:tau2-results}).

\paragraph{Gating.} Orthogonally, any intervention can be applied \emph{unconditionally} (every turn) or \emph{gated} (only when the analyzer detects substantive issues). Gating reduces cost and avoids unnecessary context disruption, which is important in long, stateful conversations where each reset discards potentially expensive-to-reobtain information (e.g., tool call results in agentic settings). On shorter, self-contained tasks, unconditional intervention is simpler and avoids false negatives from the gating classifier.

\paragraph{Matching intervention to setting.} The choice of intervention and trigger depends on deployment constraints. We use unconditional Reset for LiC, where tasks are self-contained and the programmatic template reliably captures task structure. For tau2-bench's long agentic conversations, we use Gated Reset to avoid disrupting productive tool-use sequences. For WildChat's diverse open-domain conversations, we use Rewrite to handle the wider variety of conversational formats. This flexibility---shared analysis pipeline, setting-appropriate intervention---is a feature of the framework: the analytical core (Section~\ref{sec:decomposition}) is the contribution, while the intervention strategy is a design choice practitioners make based on conversation length, statefulness, and acceptable overhead.

\subsection{Adaptation for agentic settings}
\label{sec:agentic-methods}

For tau2-bench, we adapt the analysis framework to accommodate tool-use conversations. The key modifications are:

\begin{itemize}
    \item \textbf{Environment state tracking.} The analyzer explicitly tracks the state of the external environment (e.g., account settings, diagnostic results) as revealed through tool calls, preventing loss of critical state information during context resets.

    \item \textbf{Strategic reflection framing.} Rather than framing the analysis purely as pollution detection, we reframe it as ``mid-task strategic reflection''---identifying not just what went wrong but what diagnostic avenues remain unexplored. The analysis includes a \texttt{strategic\_direction} section that highlights untried approaches.

    \item \textbf{Gated resets with max\_resets=3.} Resets are triggered only when substantive issues are found, with a cap to prevent infinite reset loops. This is critical in agentic settings where each reset discards tool results that may be expensive to re-obtain.
\end{itemize}

We also evaluate the \textbf{Rewrite} variant in this setting, testing whether LLM-generated briefings can improve upon programmatic template filling for agentic conversations.

\subsection{Toward realistic settings: full-conversation analysis}
\label{sec:soft-attention}

The structural exclusion of assistant messages from Subtask~1 exploits a property of LiC: user messages alone fully specify the task. In realistic settings---iterative design, collaborative coding, tool-use agents---the task specification may depend on prior assistant work. We investigate whether the model can learn to maintain executive function even when exposed to the full conversation.

\paragraph{Chain-of-thought decontamination.} We introduce a soft-attention variant that explicitly reasons through source attribution: (1) list every concrete requirement stated by the user with message-level provenance, (2) identify assistant-originated interpretations and flag them as hypotheses rather than facts, (3) note user overrides, (4) write the spec using only user-grounded requirements. This makes the separation between user intent and assistant interpretation an explicit reasoning step rather than a structural guarantee.

\paragraph{Memory-based decontamination learning.} We use hard-attention task specs as oracle training targets: the reflector compares soft-attention specs against hard-attention oracles to learn generalizable decontamination principles via the Dynamic Cheatsheet mechanism.

\subsection{Memory-based learning}
\label{sec:memory}

The Dynamic Cheatsheet accumulates self-reflection principles across problem instances, injected into the analyzer's prompt. For the primary hard-attention system, memory targets the approach evaluation subtask. For soft-attention experiments, memory targets spec extraction directly.

\paragraph{Update mechanism: Reflect-then-Unify.} After processing a batch of problems: (1) \emph{Reflect}---for each trajectory, an LLM generates generalizable takeaways from the outcome; (2) \emph{Unify}---a single LLM call merges new takeaways with the current cheatsheet, deduplicating and resolving contradictions. Cheatsheet length is capped at 1500 words; meta-level principles (``verify output format matches user specification'') transfer well, while task-specific content (algorithmic recipes) causes anchoring on stale patterns.

\subsection{CollabLLM adaptation}
\label{sec:compaction}

To test in a more naturalistic collaborative setting, we adapt the framework for CollabLLM evaluation using the Rewrite variant, which activates after user turn~4 and runs unconditionally: a single-pass analysis reads the full conversation and produces a task specification plus assessment, then a rewrite prompt generates a clean compacted context that replaces the conversation history. This uses full-conversation analysis (no structural exclusion) since CollabLLM conversations are genuinely collaborative.

WildChat: GPT-5-mini for all roles (respondent, judge, classifier, analyzer). CollabLLM: GPT-5-mini (reasoning\_effort: low) for assistant and context editor; GPT-4o for user simulator; GPT-5 for conversation-aware judge.

\paragraph{Replay mode (LiC).} To isolate intervention effects from conversational variance, all strategies share the same baseline conversation prefix (from an unmodified baseline run) and only the final assistant turn is regenerated with the intervention applied.

\subsection{Experimental conditions}

\paragraph{LiC---Primary conditions.} We compare our analysis-based methods against the baseline and two prior-work baselines: Omit Assistant~\citep{huang2026context} (drop all assistant messages) and Concatenate User (ERGO-style;~\citealt{khalid2025ergo}, reset and concatenate user messages). Our methods (Augment, Reset, Gated Reset) are tested with and without memory.

\paragraph{Tau2-bench conditions.} We compare four strategies: the unmodified baseline, Assistant Omission (AO; drop all assistant messages and tool results before each LLM call), Gated Reset, and Gated Rewrite. Gated Reset and Gated Rewrite are tested across two prompt versions (v9: pollution-detection framing; v10: strategic-reflection framing).

\paragraph{LiC---Soft-attention conditions.} On held-out test splits, we evaluate chain-of-thought soft-attention variants with and without memory-trained decontamination, comparing against hard-attention oracles.

\subsection{User simulator quality control (LiC)}
\label{sec:user-sim-qc}

The sharded disclosure format occasionally produces user messages that distort the original problem. We pre-screen baseline traces using an LLM judge that compares the union of user simulator messages against the original single-turn question and flags cases where critical details are absent or materially changed. Flagged samples are excluded from all conditions (3 math, 6 code, 0 database, 2 actions). This ensures accuracy denominators reflect problems the assistant could reasonably solve.

\subsection{CollabLLM evaluation methodology}

CollabLLM's standard BigCodeBench evaluation uses test-case execution, which requires exact function signatures. In the multi-turn setting, the user simulator never conveys exact function specs, making pass\_rate systematically zero for all conditions. We develop a \textbf{conversation-aware LLM judge} that evaluates the assistant's code against what the user actually asked for, using GPT-5 as judge.

\paragraph{Simple baselines are strong when rederivation is cheap.}
The most important comparison in Table~\ref{tab:lic-main} is between our analysis-based methods and the simpler prior-work baselines. This confirms a key insight: on LiC, the problem is primarily that the assistant's prior messages are harmful, and removing them is sufficient. \paragraph{Analysis adds value through intelligent consolidation.}
Our methods outperform the simple baselines on \textbf{database} (44\% vs.\ 32\%), the most schema-dependent task where raw fragmented user messages are insufficient. The task specification extraction---which consolidates scattered user requirements into a structured spec grounded in the system message's schema---provides value beyond simple message filtering. \paragraph{Context removal provides additional benefit over analysis alone.}
Reset outperforms Augment on code (+13pp), database (+8pp), and actions (+8pp). Table~\ref{tab:lic-memory} shows that memory provides consistent benefit when applied to analysis-based methods. Augment + Memory achieves the best results on math (90\%) and ties for best on database (44\%). Memory helps the analyzer produce more decisive task specifications and more concrete error identification.

\paragraph{Assistant messages are a cognitive hazard.}
When the analyzer sees assistant messages during spec extraction, performance collapses to baseline or worse (Table~\ref{tab:cognitive-hazard}). Both soft-attention variants produce analysis that is not just unhelpful but \emph{actively harmful}: soft-attention decomposed performs below baseline on math (40\% vs.\ 60\%) and code (11\% vs.\ 16\%). This is evidence that context pollution is a general property of how LLMs process multi-party conversation---even a model explicitly tasked as an independent reviewer anchors on the assistant's reasoning.

\paragraph{Contamination amplifies through chained calls.}
The soft-attention decomposed variant underperforms single-pass (40\% vs.\ 55\% math; 11\% vs.\ 21\% code). When Subtask~1 produces a contaminated specification and passes it to Subtask~2 as authoritative, contamination compounds. This is a cautionary finding for multi-stage LLM pipelines: chaining calls can amplify rather than correct errors when earlier stages are contaminated.

\paragraph{Assistant omission is catastrophic in agentic settings.}
The most striking result is that blanket assistant omission (AO) achieves \textbf{0\%} success (Table~\ref{tab:tau2-main}), compared to 45--55\% for the unmodified baseline. When all assistant messages and tool results are stripped before each LLM call, the agent loses all diagnostic progress---API call results, account lookups, troubleshooting history---and enters infinite re-lookup loops. This is the strongest possible evidence that context omission, while effective on LiC's self-contained tasks, is fundamentally incompatible with stateful, tool-use settings.

\paragraph{Context editing outperforms baseline with strategic reflection.}
With v10 prompts, which reframe the analysis as ``mid-task strategic reflection'' rather than pollution detection, Gated Reset achieves 55--60\% across two confirmation runs---consistently above the 45--55\% baseline. The strategic direction component (``what hasn't been tried?'') appears to be the key improvement, redirecting the agent toward unexplored diagnostic avenues rather than simply flagging errors.

\paragraph{LLM rewriting is harmful in data-rich agentic settings.}
Gated Rewrite underperforms both baseline and Gated Reset, dropping to 25\% with v10 prompts. The additional LLM rewrite step loses concrete tool result data through summarization, triggers false-positive resets via verbose issue descriptions, and misdirects the agent toward procedural concerns. Even with targeted fixes (v10.1: 40\%), Gated Rewrite does not match Gated Reset. In agentic settings where tool results contain structured data that must be preserved exactly, programmatic template filling is superior to LLM-generated summaries. However, as we show on WildChat (Section~\ref{sec:collab-results}), the Rewrite variant excels in open-domain conversational settings where the diversity of formats benefits from the model's flexibility.

\paragraph{Context pollution is not the dominant failure mode.}
Diagnostic analysis of baseline failures reveals that only 1 of 11 failures shows clear over-anchoring. The dominant failure modes are missing domain knowledge (4/11) and step budget exhaustion (4/11). This means Gated Reset's improvements come not primarily from removing pollution but from its strategic reflection component---redirecting the agent to explore new approaches. The executive function framing captures this: the system provides not just inhibitory control (suppressing bad reasoning) but cognitive flexibility (suggesting alternative strategies).

\paragraph{Variance and confirmation.}
Three-trial variance measurement (60 runs) shows the baseline at 53.3\% and Gated Reset (v9) at 43.3\%, with massive per-task variance from \texttt{gpt-5-mini}'s forced \texttt{temperature=1.0}. Six tasks always pass, five always fail, nine are mixed. The v10 prompt improvement (60\%, 55\% in two runs) is robust to this variance, consistently exceeding the baseline.

\paragraph{WildChat: Huang et al.\ reproduction.}
We reproduce the evaluation of \citet{huang2026context} on 30 WildChat conversations (179 evaluated turns) to test our methods on real human-AI interactions where context pollution occurs naturally.

\subparagraph{Phase 1: Confirming the AO trade-off.}
Comparing full context (FC) against assistant omission (AO) reproduces Huang's central finding: AO improves quality on \texttt{new\_ask} turns (AO wins 56.7\% vs.\ FC 34.3\%) and \texttt{feedback} turns (AO 60.5\% vs.\ FC 37.2\%), but \emph{hurts} on \texttt{no\_feedback} turns---stateful continuations where the user implicitly depends on prior assistant output (FC wins 53.6\% vs.\ AO 42.0\%). Our turn-type distribution (38.5\% \texttt{no\_feedback}) closely matches Huang's reported 33.1\%, validating the reproduction. On-topic differences are small across all types (63.7\% ties overall), confirming that the quality dimension captures the meaningful variation.

All three strategies achieve strong quality win rates against both baselines across all 173--178 turns (Table~\ref{tab:wildchat-quality}). Gated Reset is the best overall performer (86.1\% vs AO, 83.8\% vs FC) while intervening on only 72.3\% of turns. Reset achieves comparable win rates (83.0\% vs AO, 83.5\% vs FC) but intervenes unconditionally, paying the cost of unnecessary resets on turns where the conversation is already on track. On the $\sim$28\% of turns where the analyzer finds no substantive issues, Gated Reset correctly falls back to full context rather than disrupting a functional conversation. This gating is intelligent: the edit rate on \texttt{no\_feedback} turns (62.7\%) is substantially lower than on \texttt{new\_ask} (78.1\%) and \texttt{feedback} (78.6\%) turns (Table~\ref{tab:wildchat-turntype}), reflecting that stateful continuations are more often on track and less likely to benefit from intervention.

On the 76 AO failure turns---cases where Huang et al.\ identify blanket omission as actively harmful---all three strategies are even stronger. Reset achieves 90.8\% quality win rate vs AO (86.8\% vs FC), Gated Reset achieves 93.3\% vs AO (82.7\% vs FC), and Rewrite achieves 85.3\% vs AO (84.0\% vs FC). These are exactly the stateful turns where users depend on prior assistant output and where Huang et al.\ call for ``finer-grained context filtering.''

On-topic win rates follow a similar pattern (Gated Reset: 74.6\% vs AO; Rewrite: 68.5\%) but with meaningfully more ties, consistent with quality being the more discriminating dimension and suggesting the judge is not simply preferring our output format.

\subparagraph{Strategy comparison.}
The finding that Gated Reset outperforms Rewrite on WildChat (86.1\% vs 82.6\%) echoes the tau2-bench pattern where programmatic template filling beat LLM-generated summaries. However, both the absolute gap and the nature of the advantage differ. On tau2-bench, Rewrite was actively harmful (25\% vs 55--60\% for Gated Reset) because the LLM rewrite step lost critical structured data. On WildChat, both strategies perform well; Gated Reset's edge comes from its more conservative intervention policy rather than from failures in the rewrite step. This suggests the Rewrite variant is most valuable when the programmatic template cannot capture the diversity of conversational formats, while Gated Reset is preferred when accurate gating can avoid unnecessary disruption.

\subparagraph{Format bias caveat.}
The uniformly high win rates across turn types and strategies raise a format bias concern: the restructured output format (structured task spec + organized headers) may inherently present better to the judge than raw multi-turn conversation rendering, inflating absolute win rates. However, the relative comparison between Gated Reset and Rewrite is less affected since both produce similarly structured output, and the on-topic dimension shows meaningfully more ties than quality, indicating the judge discriminates between content dimensions rather than simply preferring format.

\section{Discussion}
\label{sec:discussion}
%% ============================================================

\subsection{Context curation vs.\ context removal: a spectrum of settings}

Our results across three evaluation settings---LiC, tau2-bench, and CollabLLM---paint a coherent picture of when context removal suffices and when curation is necessary.

On LiC, where tasks are self-contained and rederivation is cheap, simple omission baselines are very strong (Table~\ref{tab:lic-main}). Our analysis-based methods add value through intelligent consolidation (database) and learned analysis principles (math with memory), but the marginal benefit over brute-force removal is modest on most tasks. This characterizes the benchmark, not our approach.

On tau2-bench, the picture inverts entirely. Blanket omission catastrophically destroys performance (0\% vs.\ 55\% baseline), while Gated Reset maintains or improves upon the baseline (55--60\%). The critical difference is \emph{statefulness}: tau2-bench conversations involve tool calls whose results are essential context. Discarding this context is not a ``conservative'' strategy---it is a destructive one. The Rewrite variant underperforms in this data-rich setting (25--40\%) because the LLM rewrite step loses structured tool data, but both strategies perform well on WildChat's open-domain conversations (Gated Reset: 86\%, Rewrite: 83\%)---demonstrating that the performance gap between strategies depends on the structure of the conversation and the importance of preserving exact data.

CollabLLM and WildChat results occupy a middle ground. On CollabLLM, full-conversation analysis without structural exclusion provides +5--20pp improvement. On WildChat, all three strategies achieve 82--86\% quality win rates against AO and 80--84\% against FC across all turn types ($n$=173--178), demonstrating that even on real human-AI conversations---where context pollution occurs naturally rather than through simulation---surgical curation consistently outperforms both the unmodified conversation and blanket omission. Notably, Gated Reset is the best strategy on both tau2-bench and WildChat, suggesting that conservative, gated intervention is a robust default: intervene when the analysis finds clear issues, fall back to full context otherwise. The 72.3\% edit rate on WildChat (with only 62.7\% on \texttt{no\_feedback} turns) shows the gating is discriminating, not merely triggering less often.

\subsection{Executive function as an agent design pattern}
\label{sec:exec-function-pattern}

Our approach can be understood as a general design pattern: \emph{externalized executive function} through an agent that schedules LLM queries with custom context windows. The key insight is that different subtasks of self-reflection require different context:

\begin{itemize}
    \item \textbf{Selective attention}: Intent extraction must be shielded from contaminating content.
    \item \textbf{Performance monitoring}: Approach evaluation needs both clean intent and the messy reality.
    \item \textbf{Cognitive flexibility}: Strategic reflection (as in tau2-bench v10) identifies unexplored alternatives.
    \item \textbf{Working memory updating}: Memory accumulation needs access to outcomes across instances.
\end{itemize}

This pattern generalizes beyond our specific decomposition. Any setting where an LLM needs to reason about potentially misleading context---code review where existing code anchors the reviewer, fact-checking where the claim anchors the checker---could benefit from careful context scheduling. The executive function framing provides a vocabulary: what information should each reasoning step attend to, and what should it be inhibited from seeing?

The ``self-aware'' aspect of this framing is that the system is designed with explicit knowledge of the model's own failure modes. We do not claim the LLM is self-aware in any phenomenological sense. Rather, the system designer's awareness of context pollution as a systematic failure mode is encoded into the agent architecture---the model is made functionally aware of its limitations through the structure of the queries it receives. This is analogous to how a human might use an external checklist to compensate for known cognitive biases: the checklist does not make the human ``self-aware'' of the bias in real time, but it operationalizes the designer's understanding of human limitations.

\subsection{The cognitive hazard and its implications}

The finding that assistant messages degrade analysis quality---even for a model prompted as an independent reviewer (Table~\ref{tab:cognitive-hazard})---has implications beyond our specific setting. Any system that uses an LLM to evaluate, critique, or improve another LLM's output faces this risk. The cognitive hazard means that multi-stage LLM pipelines cannot rely on prompting to achieve selective attention. Structural data flow design---controlling what each stage sees---is the reliable approach.

The exact mechanism remains unclear: possible explanations include attention-based anchoring on the most detailed content, implicit role consistency, or information integration where the model treats all context as equally authoritative regardless of source. Understanding this mechanism is an important direction for future work.

\subsection{Limitations}

\paragraph{Sample sizes.} LiC evaluations use 19--25 samples per task; tau2-bench uses 20 tasks; WildChat uses 30 conversations (173--179 turns depending on strategy); soft-attention experiments use 12--13 per task. Effect sizes should be interpreted with appropriate caution. Tau2-bench additionally has high variance from \texttt{gpt-5-mini}'s forced \texttt{temperature=1.0}.

\paragraph{Simulated settings.} LiC, CollabLLM, and tau2-bench all use simulated users. Real conversations involve more diverse behavior including references to prior assistant responses.

\paragraph{Task scope.} LiC's single-answer tasks favor brute-force context removal. Tau2-bench provides a stronger test but is limited to customer service. Long-horizon tasks (multi-file coding, iterative design) remain untested.

\paragraph{Single model family.} All experiments use GPT-5-mini. Interaction with different architectures is unexplored.

\paragraph{WildChat format bias.} WildChat pairwise judgments may be influenced by format differences between the restructured output and raw multi-turn conversation rendering, potentially inflating absolute win rates. However, relative comparisons between our strategies (which share similar output formats) are less affected. Additionally, GPT-5-mini was used as the judge rather than GPT-5 as in Huang's original evaluation.

\paragraph{WildChat scale.} The WildChat evaluation uses 30 conversations (179 turns), while Huang used 300. A larger-scale replication would strengthen the findings.

\paragraph{Cognitive hazard mechanism.} We document the hazard but do not explain its mechanism.

\section{Conclusion}
\label{sec:conclusion}
%% ============================================================

We investigate whether LLMs can curate their own conversational context to mitigate multi-turn performance degradation, framing the problem as one of \emph{externalized executive function}. Our key findings:

\begin{enumerate}
    \item \textbf{Context curation works, with value proportional to task statefulness.} On LiC, where rederivation is cheap, simple omission baselines are competitive. On tau2-bench, where conversations involve essential tool results, omission is catastrophically destructive (0\% vs.\ 55\% baseline) while our methods maintain or improve performance (55--60\%). The value of intelligent curation over brute-force removal scales with the complexity and statefulness of the setting.

    \item \textbf{Assistant messages are a cognitive hazard.} Even a model prompted as an independent reviewer produces severely degraded analysis when exposed to assistant messages. This requires structural exclusion or learned resistance, and has broad implications for multi-stage LLM system design.

    \item \textbf{Memory-based learning teaches partial resistance} to the cognitive hazard, closing up to 65\% of the performance gap on structured tasks when the analyzer must see the full conversation.

    \item \textbf{The framework generalizes across settings.} From self-contained tasks (LiC) to agentic tool use (tau2-bench) to collaborative coding (CollabLLM) to real conversations (WildChat, 84--86\% win rates for Gated Reset vs.\ both baselines), context curation provides consistent improvements, with the strongest relative gains in settings where context removal fails. The same strategy---Gated Reset---is the best performer on both tau2-bench and WildChat, achieving this while intervening on only 72\% of turns.

    \item \textbf{Evaluation methodology matters.} User simulator quality control, replay-based isolation, and conversation-aware evaluation are necessary for reliable multi-turn measurement.
\end{enumerate}

The externalized executive function framing---an agent scheduling LLM queries with custom context windows to implement selective attention, performance monitoring, and cognitive flexibility---provides a general pattern for addressing the self-reflective capacity that models lack natively. As LLM deployment increasingly involves long, stateful, multi-turn interactions, the gap between context removal (which cannot scale) and context curation (which can) will only grow.
