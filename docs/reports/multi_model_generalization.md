# Multi-Model Generalization: Context Editing Across Model Families

**Date**: 2026-03-29
**Author**: automated runs via Claude Code

## Overview

This report evaluates whether context editing generalizes beyond gpt-5-mini to other model families. We test three additional models -- gpt-5 (full-size), DeepSeek V3.2, and Qwen 3.5 35B-A3B -- on two benchmarks:

1. **LiC htn20_52**: The 20 hardest true-negative problems per task from gpt-5.2 LiC logs, comparing S0 (baseline) against S1.5 (non-gated programmatic reset) across four task domains (math, code, database, actions).
2. **WildChat (Huang eval)**: The 76 AO-failure turns from the existing 30-conversation pilot, comparing FC, AO, S3, and S1.5 using pairwise quality judging.

The core question: is context editing a technique that benefits only a specific model, or does it address a general problem in multi-turn LLM interaction?

## Models Tested

| Model | Type | Provider | Active Params | Notes |
|---|---|---|---|---|
| gpt-5-mini | Reasoning | Azure | ~unknown | Existing baseline from prior experiments |
| gpt-5 | Reasoning | Azure | ~unknown | Full-size GPT-5, medium reasoning effort |

## Part 1: LiC htn20_52

### Experimental Setup

Identical to the original htn20_52 experiment documented in `docs/reports/htn20_52_experiment_results.md`:

- **Data**: 20 hardest true-negative problems per task from gpt-5.2 LiC logs
- **Replay**: Last-turn replay on baseline traces from `data/baseline_traces_htn20_52/{task}/`
- **Evaluators**: math_v2, code_v2, database_v2, actions (no v2)

S1.5 reflects "model X given a clean context derived from model X's own analysis of gpt-5.2's conversation." This isolates the effect of context editing from the model's own multi-turn behavior.

### LiC Analysis

**1. S1.5 improves accuracy for every model on every task except one.** The sole exception is gpt-5 actions, where S0+accum is already at 85% and S1.5 drops to 70%. This is the only model/task combination at near-ceiling S0 performance. In all other cases -- 15 out of 16 model-task pairs -- S1.5 produces substantial gains ranging from +20pp to +70pp.

**2. Smaller models benefit more.** The average S1.5 gain for Qwen 3.5 35B (3B active params) is +42.0pp, compared to +26.2pp for gpt-5-mini and +19.5pp for gpt-5. This makes intuitive sense: smaller models are more susceptible to being misled by polluted context, so cleaning that context provides a larger relative benefit. It also suggests context editing is a particularly cost-effective intervention for smaller, cheaper models.

**3. The context reset matters more than the analysis.** DeepSeek S1 database stays at 10% (identical to S0), but S1.5 jumps to 45%. Qwen S1 actions drops to 10% (worse than S0's 45%), but S1.5 recovers to 80%. Simply appending the analysis is insufficient or even harmful in some cases; the polluted context must be removed for the analysis to be useful. This is consistent with the "hard attention" hypothesis: the model over-attends to concrete (but wrong) prior assistant work even when contradicted by the appended analysis.

**4. Code evaluation errors are consistent.** All models show 5-7 code samples excluded due to livecodebench evaluation errors (syntax errors in model output that crash the code extractor). This is an evaluator limitation, not a model limitation. The error rate is similar across models, suggesting these are intrinsically problematic samples.

**5. Stronger S0 baselines do not diminish S1.5 gains.** Qwen math S0 is already at 55% (the highest S0 across all models for math), yet S1.5 still adds +20pp. gpt-5 database S0 is 27%, and S1.5 adds +38pp. The intervention does not merely help weak models reach a capability ceiling -- it helps all models overcome context pollution that was limiting them regardless of their baseline capability.

**6. gpt-5 actions regression is an edge case at ceiling.** At 85% S0 accuracy, gpt-5 is already solving 17/20 of the hardest actions problems with the polluted context. The 3 remaining failures may require information present in the conversation that S1.5's context reset discards. With the +accumulate prompt, gpt-5 appears capable of leveraging the full conversation history effectively on this task, making context editing a net negative. This pattern was not observed for any other model on actions (all others show +35pp gains from much lower baselines).

The Phase 1 data (turn classification, FC vs AO judgments, AO failure identification) comes from the original gpt-5-mini run. - **Conditions**: FC, AO, S3 (LLM compaction), S1.5 (programmatic reset)
- **Evaluation**: Pairwise quality judging (Huang's prompt)

### WildChat Analysis

**1. DeepSeek shows moderate S3/S1.5 gains on WildChat.** S3 beats AO 61.8% to 28.9% on quality. S1.5 also wins, 59.2% to 31.6%. These are solid gains, though more modest than gpt-5-mini's 87%/91%. The effect is consistent across turn types: new_ask (60.9%), feedback (50.0%), no_feedback (67.6%).

**2. gpt-5 shows S3/S1.5 losing to baselines.** AO beats S3 47.3% to 37.8%, and FC beats S3 51.4% to 31.1%. S1.5 is nearly a coin flip vs AO (39.2% vs 40.5%). This is a sharp contrast with the LiC results where gpt-5 showed consistent S1.5 gains. gpt-5's no_feedback turns are the weakest: AO wins 56.8% to S3's 32.4%.

**3. gpt-5 may be strong enough that context editing hurts on open-ended tasks.** The LiC results showed gpt-5 S0 actions already at 85% (near ceiling), with S1.5 causing a regression. A similar pattern may be at play on WildChat: gpt-5's AO and FC responses on open-ended conversations are already high quality, and the compaction/reset process discards useful context that gpt-5 could otherwise leverage. This is consistent with the finding that smaller models (gpt-5-mini, DeepSeek) benefit more from context editing.

**4. The judge-as-respondent confound remains.** Each model judges its own outputs. gpt-5-mini showed 87% S3 win rates when self-judging; gpt-5 shows 38%; DeepSeek shows 62%. Part of this variation is real (different model capabilities on WildChat) and part may be judge calibration. The corrected same-model baselines ensure we're not confounding model quality with intervention quality, but cross-model comparison of absolute win rates is still unreliable.

**5. S3 vs FC is nearly a coin flip for DeepSeek, but FC wins for gpt-5.** DeepSeek S3 vs FC is 47.4% to 46.1% (essentially tied). gpt-5 S3 vs FC is 31.1% to 51.4% (FC wins clearly). This suggests that on AO-failure turns (where FC > AO by definition), the full context carries information that S3 compaction loses. For gpt-5, this information loss outweighs the benefits of compaction. For DeepSeek, the tradeoff is roughly neutral.

**6. Feedback turns remain the weakest category for S3.** For gpt-5: S3 wins 43.8% vs AO's 50.0% on feedback (the only turn type where S3 isn't clearly losing). For DeepSeek: S3 wins 50.0% vs AO's 43.8%. In both cases, feedback is where S3 does worst relative to its performance on other turn types. This is expected -- feedback turns reference specific prior assistant work, and compaction may lose the details being referenced.

**7. LiC and WildChat results diverge for gpt-5.** On LiC (ground-truth evaluation), gpt-5 gets +19.5pp average S1.5 gain. On WildChat (pairwise judging), S1.5 is neutral or negative. Possible explanations:
   - LiC evaluates whether the answer is correct; WildChat evaluates which response a judge prefers. A response can be correct but stylistically less preferred.
   - LiC problems have clearly wrong prior work that context editing removes. WildChat conversations are more ambiguous -- the prior assistant context may be imperfect but still useful.
   - The AO-failure subset is specifically where the full context helps (FC > AO). This biases toward cases where context editing (removing context) is the wrong intervention.

**8. The initial runs (without `--regenerate-baselines`) inflated S3/S1.5 win rates.** Before correction, gpt-5 showed S3 81.6% vs AO 10.5%; after correction, S3 37.8% vs AO 47.3%. The inflation came from comparing a stronger model's S3 against a weaker model's (gpt-5-mini's) AO/FC. This is a critical methodological note: Phase 2 must regenerate baselines when changing the respondent model.

### Judge-Context Structural Bias

The pairwise judge prompt (`huang_eval/prompts/pairwise_judge.txt`) shows both responses against the **original, unmodified conversation** as context. Specifically, `context_for_a` and `context_for_b` are both set to `_format_context(turns[:turn_index])`, which is the full conversation history including all prior assistant messages. The judge never sees the compacted or modified context that S3/S1.5 used to generate the response.

This creates a structural bias:

- **FC responses** were generated from the same full context the judge sees. They will be maximally coherent with it.
- **AO responses** were generated from a subset of the judge's context (user messages only). They may occasionally reference things differently but are still grounded in the same conversation.
- **S3/S1.5 responses** were generated from a compacted context the judge never sees. If the analyzer reformulates the task specification or reframes the problem, the response may address the right task but look like it's "not following the conversation" from the judge's perspective.

This bias is not specific to any judge model -- it's inherent in the evaluation design (which follows Huang et al.'s methodology). However, it may interact more strongly with gpt-5 as judge because:

1. gpt-5 is a more capable model and may be more attuned to conversational coherence, penalizing responses that seem disconnected from the conversation flow.
2. When gpt-5 is also the respondent, its FC/AO responses are generated in a style that gpt-5-as-judge naturally recognizes and prefers, while its S3/S1.5 responses (generated from reformulated context) may deviate from that style.
3. Weaker judges (like gpt-5-mini) may focus more on surface-level response quality and less on conversational coherence, making them less sensitive to the context mismatch.

### Paper Recommendation for WildChat Results

**For the paper, we recommend reporting gpt-5-mini and DeepSeek WildChat results but excluding or caveating gpt-5.** The rationale:

- **gpt-5 as respondent AND judge** creates a double confound: the judge may prefer responses stylistically consistent with its own generation patterns from less-modified contexts, and it may be more sensitive to the judge-context structural bias described above. These two effects compound in the same direction (favoring FC/AO over S3/S1.5).
- **gpt-5-mini and DeepSeek as self-judges** have only the single self-judge confound. This is inherent to any LLM-as-judge setup and is acceptable given that the alternative (no judge, or human judging at this scale) is impractical.
- **gpt-5 could serve as a fixed external judge** for all models' responses, which would eliminate the self-judge confound. However, the judge-context structural bias would remain, and a run using gpt-5 to re-judge the initial DeepSeek responses (before baseline regeneration) showed the same reversal pattern -- suggesting this is primarily a judge-context issue, not just self-preference.
- **LiC results for all models (including gpt-5) are unaffected** since they use ground-truth evaluation with no judge model.

## Part 3: WildChat Memory Learning

Tests whether the cheatsheet memory system (developed for LiC) can improve S1.5 analysis quality on WildChat. Memory is injected into the analyzer's compare query (Query 2), same as in LiC. See `docs/memory_learning.md` for background on the memory system.

### Experiment 1: gpt-5-mini (Online Learning)

**Setup**: gpt-5-mini for all roles (respondent, analyzer, judge, learner). Processes 76 AO-failure turns sequentially in batches of 5. After each batch, the system reflects on results (Reflect-then-Unify) and updates the cheatsheet. Later turns benefit from accumulated memory.

```bash
python scripts/run_wildchat_memory.py \
    --phase2-dir outputs/huang_eval/phase2/2026-03-24/02-54-36 \
    --phase1-dir outputs/huang_eval/phase1/2026-03-24/02-22-57 \
    --model gpt-5-mini --batch-size 5 --seed 42
```

**Output**: `outputs/huang_eval/memory/2026-03-30/04-00-10`

**Results**:

| Comparison | S1.5 baseline (n=76) | S1.5+memory (n=75) |
|---|---|---|
| S1.5 vs AO | S1.5 90.8%, AO 9.2% | S1.5 86.7%, AO 13.3% |
| S1.5 vs FC | S1.5 86.8%, FC 13.2% | S1.5 80.0%, FC 18.7% |

**Outcome**: No improvement. Memory did not help and may have slightly hurt. The baseline S1.5 win rate was already 91% -- there is almost no headroom for improvement. The 4pp drop is within expected variance for a non-paired comparison (different turn ordering, regenerated responses).

The memory system did learn a rich 1250-word cheatsheet covering task spec construction, reset-vs-in-place heuristics, persona preservation, and feedback handling. The learning mechanism works, but these patterns are already implicit in the v8 analyzer prompt, so stating them explicitly adds redundancy rather than new information at this performance level.

### Experiment 2: DeepSeek V3.2 (Train/Eval Split)

Motivated by the ceiling effect with gpt-5-mini, we tested DeepSeek V3.2 which has a much lower baseline S1.5 win rate (59% vs AO), providing headroom for memory to help.

**Design changes** from Experiment 1:
- **Train/eval split**: 1/3 of turns (25) used for training, 2/3 (51) for evaluation. Memory is learned offline from train results, then frozen for eval. This avoids confounding memory quality with ordering effects.
- **Separate judge**: gpt-5-mini judges all comparisons (respondent and judge are different models). This avoids the self-judging confound.
- **Parallel execution**: Turns within each phase run concurrently. Total runtime ~20 minutes vs ~5 hours for the sequential gpt-5-mini run.
- **Controlled comparison**: Both eval conditions (baseline and +memory) run on the same 51 turns with the same judge randomization seed. The only difference is whether the analyzer's compare query includes the cheatsheet.

```bash
python scripts/run_wildchat_memory.py \
    --phase2-dir outputs/huang_eval/phase2/2026-03-29/21-43-34 \
    --phase1-dir outputs/huang_eval/phase1/2026-03-24/02-22-57 \
    --model deepseek/deepseek-v3.2 --judge-model gpt-5-mini \
    --train-split 0.33 --seed 42
```

**Output**: `outputs/huang_eval/memory/2026-03-30/13-57-16`

| **S1.5 vs FC** | S1.5 72.5% | **S1.5 80.4%** | **+7.9pp** |

### Memory Analysis

**1. Memory produces a clear, controlled improvement for DeepSeek.** On the same 51 eval turns, with the same judge and same randomization, S1.5+memory wins 86.3% vs AO compared to 72.5% baseline -- a +13.8pp gain. This is a properly controlled comparison: the only variable is the cheatsheet in the analyzer's compare query.

**2. Feedback turns show the largest gain (+30pp).** Memory learned to preserve user references to prior assistant output, treat feedback as high-value context, and prefer in-place corrections over full resets when the user is building on specific prior work. This is precisely the pattern that made feedback turns the weakest category in prior experiments. With memory, DeepSeek achieves 100% S1.5 win rate on feedback turns (n=10).

**3. Memory helps most where the baseline is weakest.** The no_feedback category had the lowest baseline (64.0%) and shows a +12.0pp gain. The new_ask category was already at 87.5% and gained only +6.3pp. This mirrors the ceiling effect: memory is most valuable when there is room to improve.

**4. The ceiling effect explains gpt-5-mini's null result.** gpt-5-mini's baseline was 91%, leaving ~7pp of headroom. DeepSeek's baseline was 59% (Phase 2 self-judged) or 72.5% (eval split, gpt-5-mini-judged), leaving much more room. The memory system works in both cases, but the effect is only measurable when the baseline isn't already near-ceiling.

**5. Cross-model judge eliminates self-judging confound.** Using gpt-5-mini as judge for DeepSeek's responses means the win rates reflect an external assessment, not self-preference. This makes the DeepSeek+memory result more robust than either the gpt-5-mini self-judged result or the DeepSeek self-judged result from Part 2.

**6. Train set size was sufficient.** 25 training turns produced a 1026-word cheatsheet that generalized to 51 unseen eval turns. This suggests the WildChat domain has learnable patterns that transfer across conversations, even with modest training data.

## Limitations

1. **Single run per condition.** With n=20 for LiC and n=76 for WildChat, differences under ~15pp may not be statistically significant. The consistent direction of effects across all models partially compensates for this.

2. **Replaying foreign conversations.** All LiC models replay gpt-5.2 baseline conversations. S0 results reflect how well each model handles gpt-5.2's polluted context, not its own multi-turn behavior. This is a controlled comparison but may not reflect real deployment scenarios.

3. **Judge-context structural bias on WildChat.** The judge sees the original full conversation but S3/S1.5 responses were generated from compacted context. This structurally favors FC/AO responses that are more coherent with the judge's view. See "Judge-Context Structural Bias" section above. Combined with each model self-judging, this makes the gpt-5 WildChat results unreliable for the paper (see "Paper Recommendation").

4. **Same analyzer prompts for all models.** The v8 analyzer and S3 compaction prompts were developed and tuned using GPT models. They may not be optimal for DeepSeek or Qwen. Prompt sensitivity could explain some of DeepSeek's weaker WildChat results.

5. **Code error exclusions.** 5-7 code samples per model are excluded from evaluation due to livecodebench syntax errors. Treating errors as incorrect (normalizing to /20 denominators) would lower all code accuracies proportionally.

6. **No cost normalization.** OpenRouter and Azure have different pricing. DeepSeek and Qwen are substantially cheaper per token than gpt-5-mini or gpt-5, which affects the cost-benefit analysis of running the analyzer.

## Conclusions

Context editing via S1.5 produces large, consistent accuracy gains across four model families on the LiC benchmark. The effect is not specific to GPT models, not specific to a particular parameter scale, and not limited to a single task domain. Smaller models benefit more (+42pp average for 3B-active Qwen vs +26pp for gpt-5-mini), suggesting context editing is especially valuable when model capability is the binding constraint.

On WildChat (with corrected same-model baselines), DeepSeek shows moderate S3/S1.5 gains (S3 62% vs AO 29%), while gpt-5 shows S3/S1.5 losing to baselines (S3 38% vs AO 47%). However, the gpt-5 WildChat result is confounded by gpt-5 serving as both respondent and judge, compounded by a structural bias in the judge prompt that shows the original (uncompacted) conversation as context for both responses. We recommend reporting gpt-5-mini and DeepSeek WildChat results in the paper and excluding or heavily caveating gpt-5. The LiC results for gpt-5 (ground-truth evaluation, no judge) remain valid and show clear S1.5 gains.

The cheatsheet memory system, originally developed for LiC, transfers to WildChat and produces a measurable improvement when there is headroom. DeepSeek S1.5+memory achieves 86.3% win rate vs AO (compared to 72.5% baseline), with feedback turns improving from 70% to 100%. The effect is absent for gpt-5-mini (91% baseline, no headroom). This demonstrates that memory-based learning from a small training set (25 turns) can generalize to unseen conversations in a new domain.

The programmatic template approach (S1.5) is consistently competitive with or better than LLM compaction (S3) across all models and both benchmarks, reinforcing the finding that the primary intervention is context cleanup, not sophisticated rewriting.
